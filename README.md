# Netspace

[![自查](https://github.com/GAVIN/netspace/actions/workflows/check.yml/badge.svg)](https://github.com/GAVIN/netspace/actions/workflows/check.yml)

手机能看到的网络，画成一个可以走进去的空间。

每一个亮起来的点，都是一台真实存在的机器 —— 你的网关、运营商出口、DNS 解析器、根服务器，以及互联网上的真实站点。没有一个是示意图，全都是真的连过去测出来的。

点的高度是延迟。越慢的越往下沉，在海平面以下堆成一片。国内站点在内圈，国外在外圈，中间隔着一条水线。

你要做的只是拖动屏幕，从自己的设备出发，往外走。

## 三件不太一样的事

**它测的不是"能不能通"，而是"哪一段不通"。**
DNS 解析、TCP 握手、TLS 证书、逐跳延迟 —— 每一段单独计时、单独判定。一个站点打不开，你能看到是解析被污染了、还是证书不对、还是单纯太慢。

**它对 DNS 污染只报证据，不下判决。**
向多个解析器并发查询、比对组织归属，再和权威 NS 的答案交叉验证。但结论永远带着置信度和注意事项 —— 因为像百度这种多 CDN 站点，组织归属本来就会分歧，那是正常的，不是污染。

**它的浏览器把网页当敌意输入处理。**
页面里藏着的"忽略之前的指令"会被识别、剔除、标红。防护靠的是确定性的规则，不是模型 —— 小模型对正常文本也会误报。

## 功能

### 网络可视化

- **真实测量**：TCP 握手计时、TLS 证书核验、逐跳延迟、端口探测
- **DNS 污染检测**：向多个解析器并发查询，比对组织归属；再和权威 NS 的答案做交叉验证
- **拓扑发现**：从种子站点的 TLS 证书 SAN 字段里挖出关联域名，递归展开
- **实时监测**：出口 IP 变化、站点掉线、延迟突增、DNS 污染与恢复，都记进事件时间线
- **自适应**：自动识别 Wi-Fi / 蜂窝网络，调整超时、并发、探测规模

### 内置浏览器

- 通过本机代理抓取并渲染网页，**自动剥离脚本**
- **提示词注入防护**：页面里藏着的"忽略之前的指令"这类内容会被识别、剔除、标红
- **智能阅读模式**：提取正文，标注剔除掉的可疑段落
- **就页面提问**：本地模型回答，全程离线

### 本地 AI

- 模型完全跑在设备上，**不联网、不上传任何内容**
- 模型可下载（内置目录）或**自己导入** GGUF 文件
- 对话记录存在本机，可随时清空

### 模型上下文协议（MCP）

把网络测量能力暴露给任何支持 MCP 的 AI 客户端 —— 13 个工具，JSON-RPC 2.0 over stdio。

<br>

## 界面

### 性能 —— 主板视图

把设备画成一块主板：SoC 封装、核心簇、GPU、内存、存储。核心方块的填充高度 = 该核当前频率在其最低~最高频率区间里的位置，**哪个核在跑一眼就看出来**。

![性能面板](docs/perf.png)

> Android 禁止应用读 `/proc/stat`，所以活跃度不是时间片统计，而是用频率推算的 —— 对芯片图来说这反而更贴切。

### 模型管理

下载、导入、删除。导入走系统文件选择器（SAF），**不需要任何存储权限**。

![模型管理](docs/models.png)

其余界面：**空间**（三维网络拓扑）、**浏览**（带注入防护）、**AI**（本地对话）、**MCP**（工具清单与接入配置）。

<br>
